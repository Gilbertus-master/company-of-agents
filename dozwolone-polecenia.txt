# Allowlist of commands and tools – the permissions hook blocks BY DEFAULT everything that is not listed here.
#
# How it works (.claude/hooks/uprawnienia.py):
#   - a Bash command is split into parts (;  &&  ||  |  $(…)  `…`  subshells, bash -c '…', find -exec, xargs)
#     and EVERY part must start with an entry from the [polecenia] (commands) section;
#   - an entry is a command name or a name with a subcommand ("gh pr view" admits gh pr view, but not gh pr merge);
#   - actions from uprawnienia.yaml (merging a PR, deployment, sending, writing over HTTP…) have their own levels
#     and go their own way – an entry here does not unlock them;
#   - the absolute bans from zasady.md (git reset --hard, sudo, eval…) apply regardless of this list;
#   - a command not on the list = action "spoza_listy" (level: owner) – it passes only with an accepted decision
#     (DECYZJA=D-RRRRMMDD-NN <command>) or after being added here.
#
# Changing this list is "zmiana_zasad_lub_uprawnien": owner only, through a PR. An agent never adds commands for itself.
# This is a guard rail, not a sandbox: an interpreter on the list (python3, node, bash script.sh) will run any code
# it is given. The shorter the list, the stronger the guard rail – remove what your organisation does not use.
