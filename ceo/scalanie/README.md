# Merge queue

**Why:** a PR with a reviewer verdict of "OK" for the current commit should be merged within fifteen minutes, not wait for a CEO run.
Work that is approved but not merged is inventory: it delivers no value, it goes stale and it pushes later PRs into conflict.

**Overriding rule:** a false "do not merge" costs fifteen minutes, a false "merge" costs production. Every doubt ends with an
entry for whoever can resolve it, never with a merge.

## Who does what

| Who | What it does | What it does not do |
|---|---|---|
| Script `scripts/scalanie.py` | computes the facts and the **class** of every open PR, writes orders, keeps the state and the log | does not merge, changes nothing in GitHub |
| Merge agent (task `scalanie`, every 15 min) | performs a closed list of actions from the table: merges `GOTOWY`, re-targets the base, re-runs CI, sends out notices | does not change the class, does not touch PR code, does not resolve conflicts |
| Reviewer | records the verdict with machine fields (`recenzent/stan.json`) | does not merge |
| CEO | decides on classes `WARUNEK`, `DECYZJA`, `WYJATEK`, `MIGRACJA`; holds and releases; merges as a stand-in only with `REZERWA_CEO: TAK` | does not fill in verdict fields on the reviewer's behalf |
| Permissions hook | before every `gh pr merge` asks the script's gate; always blocks merges via the API | – |
| Owner | decision `D-…` for rules, permissions, policies and class B migrations | – |

Every obstacle goes straight to whoever removes it (author, reviewer, CEO) – once per commit and class. Nobody waits for a review.

## Agent run (every 15 min)

1. `blokada scalanie-<konto>` → token and a private working directory (a separate worktree on a fresh main branch; the agent does not dirty the shared directory).
2. `tabela` → rows with the class, the addressee and ready-made commands.
3. Actions: `GOTOWY` → command from the table + `potwierdz`; `PRZEPNIJ` → `przepiecie`, `zapisz`, base change, `odnotuj`; `BRAK_CI` → CI re-run + `odnotuj`; everything else → `zglos`.
4. `zapisz` (commit of the queue's own files on a fresh main branch, up to 3 attempts, no rebase and no `--force`).
5. `odblokuj`. Report of at most 8 lines.

Full task text: `flota/szablony/tresc/scalanie.md` → `ceo/handoff/prompty/scalanie.md` (generated by `flota/generuj.py`).

## Row classes

| Class | When | Addressee |
|---|---|---|
| `GOTOWY` | verdict `scalenie: tak` for the current commit, base = main branch, no conflict, CI green, no restricted files or migrations, no stop label | the agent merges |
| `PRZEPNIJ` | parent PR merged, the PR's base still points at its branch | the agent changes the base (after saving the file list) |
| `BRAK_CI` | no check at all | the agent re-runs once; after `brak_ci_eskalacja_min` → CEO |
| `KONFLIKT`, `CI_CZERWONE`, `KOLIZJA_MIGRACJI` | conflict with the main branch, red tests, migration number taken | author (from the branch name) |
| `NOWY_HEAD`, `BRAK_WERDYKTU`, `NIEJASNY`, `PO_PRZEPIECIU` | verdict is for another commit, no verdict for longer than `pr_bez_werdyktu_min`, verdict without machine fields, different file list after a base change | reviewer |
| `WARUNEK`, `DECYZJA`, `WYJATEK`, `MIGRACJA`, `DO_ZWOLNIENIA` | condition in the verdict, stop label, restricted files or incomplete file list, database migration, held for checking | CEO |
| `GLOWNA_CZERWONA`, `REJESTR` | red CI on the main branch ("stop the line"), unreadable hold register | CEO, entry **PILNE** (urgent) |
| no movement | `CZEKA_NA_RODZICA`, `ZALEZNOSC`, `CI_TRWA`, `NIE_SCALAC`, `WSTRZYMANY`, `SZKIC`, `SWIEZY`, `CZEKA_NA_GLOWNA`, `NIEZNANY` | nobody – waits for an event |

The order of checks is fixed and starts with the strictest: PR state → verdict → base → conflict → CI → files → migrations → labels.

**CI = the latest run of each check.** `statusCheckRollup` contains every run of a check on the head, including red ones from
before a re-run; for each key (workflow, check name or status context) the queue takes only the run with the latest start
time (an unfinished one – `0001-01-01` – counts as the newest). A tie in time, or no time with several runs = the worst result
(red). A re-run that turns CI green therefore clears `CI_CZERWONE` without an empty commit.
A CEO hold overrides every class. The table ends with the line `REZERWA_CEO: TAK|NIE – <powód>`.

## Reviewer verdict – machine fields

`recenzent/stan.json → recenzje["<klucz>"]` (key: PR number in the product repository, `<nazwa-repo>#<numer>` in the others):

| Field | Value |
|---|---|
| `sha` | the commit the verdict applies to (at least 7 characters) |
| `wynik` | `OK` / `POPRAWKI` / … – prose for humans |
| `scalenie` | `tak` · `nie` · `warunek` – **without this field the PR will not be merged** (`NIEJASNY`) |
| `warunki` | list of conditions, when `scalenie: warunek`; machine forms (the whole condition, nothing added): `po #N` / `po <nazwa-repo>#N` (the queue waits until that PR is merged) and `zielony <check> na head` (a name with spaces in \`…\`, e.g. \`Testy / e2e\`; met when the **latest** run of that check on the current head is `SUCCESS` – then no CEO needed; absent, skipped or red = `WARUNEK`). Any other condition goes to the CEO |
| `kroki` | actions after the merge (performed by the CEO or the relevant agent, not the merge agent) |
| `klasa_migracji` | `{"<plik migracji>": "A" \| "B"}` – every migration in the PR; no class = treated as class B |
| `kiedy` | `RRRR-MM-DD GG:MM` – time to merge is counted from this moment |
| `po_przepieciu` | `true` when the reviewer looked at the PR after the base change |

## CEO commands

```
python3 -I scripts/scalanie.py                        # tabela + REZERWA_CEO
python3 -I scripts/scalanie.py wstrzymaj <klucz> "powód" [--head]
python3 -I scripts/scalanie.py zwolnij <klucz> "uzasadnienie"
python3 -I scripts/scalanie.py miary --dni 7          # median and p90 of verdict → merge time, three live thresholds
python3 -I scripts/scalanie.py bramka "<polecenie>"   # will this merge get through the hook
```

- **A condition outside the verdict = `wstrzymaj`.** A note in chat or in memory will not stop the agent; the `wstrzymane.json` register will.
  A hold lasts until revoked by default (a new commit does not lift it); `--head` binds it to the current commit.
- **The CEO merges only under a lock** (`blokada ceo-czat` in a conversation, `blokada ceo-przebieg` in a run) and only when the table says
  `REZERWA_CEO: TAK` or the row has a class from the CEO's own path. After the work, `odblokuj`.
- **An unreadable `wstrzymane.json` stops all merges** – the CEO fixes the file before doing anything else.
- `BRAK_CI` after escalation: the CEO checks whether the repository has PR tests at all; if not – adds it to `bez_ci` in the settings (via a PR). Never merges "on trust".
- After its own change in the queue the CEO checks its own inbox (`zlecenia/ceo.md`) and the architect's inbox – a CEO run may have ordered the same thing meanwhile.
- Before resolving a conflict in someone else's PR: `git fetch` and a check of the branch commit – the author often does it within minutes.

## Gate in the permissions hook

Every `gh pr merge` goes through `bramka()` in the script. Only one form of the command is allowed:
`gh pr merge <nr> --repo <właściciel/nazwa> --<metoda> --match-head-commit <pełny SHA>` – no `--admin`, `--auto`, second number or shell substitutions.

| Situation | Who may merge | Additional conditions |
|---|---|---|
| class `GOTOWY` | any role | valid merge lock; SHA = the PR's current commit; method from the settings |
| `WARUNEK`, `DECYZJA`, `WYJATEK`, `MIGRACJA` (class A), `GLOWNA_CZERWONA`, `CZEKA_NA_GLOWNA` | CEO only | lock taken as `ceo-czat` or `ceo-przebieg`; no hard obstacle (conflict, red CI, no verdict for the commit, hold) |
| files `zasady.md`, `uprawnienia.yaml`, `.claude/`, `polityki/` in the organisation repo; class B or unclassified migration; incomplete file list | CEO only, with an owner decision | as above + prefix `DECYZJA=D-RRRRMMDD-NN` before the command |
| any other class | nobody | first remove the obstacle |

The gate reads settings, verdicts and holds from the main branch on the server (after `git fetch`), not from the local directory –
a local file change opens nothing. An error or a timeout (40 s) = refusal. The hook blocks merges via the API (`gh api …`) without asking the gate.

**Emergency stop:** the file `bezpieczenstwo/HALT` also stops the queue – `blokada` exits with code 14, the gate refuses
every merge (including from the CEO path and from the private working directory). The operator removes the file.

## Files

| File | Who writes it | What it contains |
|---|---|---|
| `ustawienia.yaml` | CEO via PR | main branch, method, lists `wyjatki`, `reguly`, `wlasciciel`, `migracje`, `etykiety_stop`, protocol number |
| `wstrzymane.json` | CEO only (`wstrzymaj`/`zwolnij`) | holds with a reason |
| `stan.json` | script (`zapisz`) | notices already sent, records from before a base change |
| `dziennik.jsonl` | script (`potwierdz`) | one line per merge: who, when, commit, minutes since the verdict (merged with `merge=union`) |
| `ceo/kontrole/progi.yaml` | CEO | queue thresholds: CEO reserve 45 min, lock 30 min, missing-CI escalation 30 min, contested files from 3 PRs |

## Lessons built into the design

- **The merge tool goes through review before it is switched on**, not after the first wrong merge.
- **Task text and script are swapped together** – protocol number in both; mismatch = code 13 and no lock (an old task with a new script will not leave a lock for half an hour).
- **The exception list is narrow and explicit** – every pattern is a path whose wrong merge hurts; everything else goes fast.
- **Contested files** (changed by ≥ 3 open PRs, line `PLIKI SPORNE` in the table) are the main cause of conflicts – the architect splits such a file or turns it into a generated one.
- **The account limit also stops the merge agent and the CEO reserve** – after the limit renews the operator starts the `scalanie` task straight away ("Run now"). A run killed halfway leaves a lock; the next one takes it over after 30 min.
- **"Stop the line"**: with a red main branch no changes are added – fix first.

## Limits you need to know about

- The lock and the agent's heartbeat are files on one machine and rely on cooperation. With runs from several machines exclusivity comes from GitHub (a merge with `--match-head-commit` succeeds once), and the state in the repo is idempotent.
- The gate protects against mistakes and against a command slipped in through PR content, not against deliberate circumvention (alias, script, another shell). **The real boundary is GitHub branch protection** – the operator sets it up at start: PR required, tests required, no pushing with `--force`.
- All agents act with one GitHub identity – "who merged" comes from the queue log, not from GitHub. A merge without a log entry is possible; reconciliation check B-11 (`ceo/kontrole/kontrole.md`) detects it.
- The CI state of the main branch is checked on a best-effort basis: an unknown state does not stop the queue (the table prints a note).
- GitHub returns at most 100 files per PR – a larger PR gets class `WYJATEK` and goes to the CEO.
- A **PILNE** order does not wake the addressee – it will be read on the next run; urgency shortens the deadline, not the reaction time.
- In the organisation repo agents push changes directly to the main branch, so the `reguly` list only applies to PRs; direct rule changes are guarded by the permissions hook and follow-up review.
- The template does not automate database migrations: class A → the CEO merges and applies, class B or no class → owner decision.
- The agent role (`AGENT_ROLA` or the `.agent-rola` file) in the private working directory is empty – which is why the `GOTOWY` path does not depend on the role, while the CEO path requires both the role and a lock taken as `ceo-…`.

## Metrics

`python3 -I scripts/scalanie.py miary` – median and p90 of minutes from verdict to merge, number of PRs with an OK verdict not merged
for over 2 h (threshold 3), PRs in conflict (threshold 3), minutes since the agent's last run (threshold 45). Breaches are read by the
weekly review and the CEO's group B checks.
